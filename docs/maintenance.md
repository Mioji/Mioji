# Profile maintenance

The profile README and every image it shows are generated by
`tooling/generate.py` from committed inputs. The generator uses the Python
standard library only (Python 3.12 or newer) and never touches the network
unless asked to refresh the data snapshot.

## Repository layout

| Path | Role |
| --- | --- |
| `configs/profile.json` | Identity, contacts, section order and project catalog |
| `configs/skills.json` | Skill badges grouped under locale heading keys |
| `configs/theme.json` | Palette, font stacks, artwork overlays and badge geometry |
| `configs/data/snapshot.json` | Validated public GitHub data; written by `--fetch` |
| `locales/readme/<code>/strings.json` | Copy, lists and number and date formats of a locale |
| `locales/readme/template.md` | Skeleton shared by every generated README |
| `assets/profile/` | Banner and panel artwork with their generation prompts |
| `tooling/profilegen/` | Generator package; module roles are listed in `__init__.py` |
| `tooling/tests/` | Test suite |
| `tooling/requirements-dev.txt` | Hash-pinned development tools |
| `.github/workflows/profile.yml` | Verification and the daily refresh |
| `LICENSE`, `LICENSES/`, `REUSE.toml` | Licensing terms, license texts and per-path assignment |

Generated, never edited by hand:

| Path | Content |
| --- | --- |
| `README.md` | Default (English) profile |
| `locales/readme/<code>/README.md` | Profile of every other locale |
| `assets/generated/shared/` | Language, contact and skill badges |
| `assets/generated/readme/<code>/` | Localised panels, desktop and compact variants |

The generator owns these paths completely: a file there that the current
configuration no longer produces is deleted on the next run.

## Commands

Run from any directory:

```sh
python tooling/generate.py            # render from the committed snapshot
python tooling/generate.py --check    # fail if any generated file is stale
python tooling/generate.py --fetch    # collect a new snapshot, then render
```

`--fetch` reads an optional token from `GH_TOKEN`. Without it GitHub allows
60 anonymous requests per hour per IP address, which is enough for one run.

Development checks, identical to CI:

```sh
python -m venv .venv && . .venv/bin/activate
python -m pip install --require-hashes -r tooling/requirements-dev.txt
ruff check . && ruff format --check . && mypy && pytest
```

To update a tool, edit `tooling/requirements-dev.in` and regenerate the lock
file with the command recorded at its top.

## Common changes

Every input is validated strictly: unknown keys, missing keys, unused locale
strings and malformed values are errors that name the file and the JSON path.

- **Add a project.** Append an entry to `catalog.projects` in
  `configs/profile.json` with keys `repository` (`owner/name`),
  `description_key`, `status` (`active`, `development`, or `archived`),
  `visibility` (`public` or `private`), and `background_key`. Add the
  `description_key` text to every `locales/readme/*/strings.json`, and add
  `assets/profile/backgrounds/projects/<background_key>.webp` (valid WebP up
  to 1,500,000 bytes) with its prompt in
  `assets/profile/backgrounds/prompts/projects/<background_key>.md`. For a
  `public` project, run `python tooling/generate.py --fetch` so the snapshot
  records it; otherwise run `python tooling/generate.py`.
- **Add a contact.** Append an entry (up to 8 total) to `contacts` in
  `configs/profile.json` with keys `id` (lowercase slug), `label`, `mark`
  (up to 3 display columns), `href` (`https://` URL or `mailto:` address),
  `accent` (a colour token in `configs/theme.json`), and optional `enabled`
  (set to `false` to hide an entry without deleting it). Adjust
  `badges.contact.canvas_width` in `configs/theme.json` if a new label is
  wider than the existing ones.
- **Add a skill.** Append an entry (up to 24 per group) to `configs/skills.json`
  with keys `label`, `mark` (up to 3 display columns), and `url` (`https://`).
  Labels with punctuation or non-ASCII characters (such as `C++` or `Node.js`)
  must also define a lowercase `id` used as the asset stem. To start a new
  group, add a new object key matching a heading key defined in every
  `strings.json`.
- **Reorder or hide sections.** Sections in `layout.sections` render in list
  order and are numbered by position among enabled ones. Set `"enabled": false`
  to omit a section from every README along with any unreferenced panels or
  skill badges.
- **Add a language.** Copy `locales/readme/en/` to `locales/readme/<code>/`,
  set `locale_code` to the directory name and `language` to its endonym,
  translate `content` and `structured_lists`, and adjust `locale_format` (and
  `badges.navigation.canvas_width` in `configs/theme.json` if the endonym is
  wider than the existing navigation badges).
  Date patterns (`date_format`) accept `%Y %m %d %%`, and timestamp patterns
  (`timestamp_format`) accept `%Y %m %d %H %M %S %%`, because month and
  weekday names would depend on the machine's C locale. The new locale
  appears in the language switcher automatically.

Run `python tooling/generate.py` afterwards and commit inputs and outputs
together; CI rejects a commit whose generated files are stale.

## Licensing

The repository uses two licenses, assigned per path in `LICENSE`
(Section 1) and mirrored in `REUSE.toml` and the SPDX headers of source
files:

| License | Scope |
| --- | --- |
| MIT | `tooling/`, `.github/`, `docs/`, the README template, `configs/theme.json`, `configs/skills.json`, project metadata and the generation prompts |
| CC BY-NC-ND 4.0 | Artwork in `assets/profile/`, everything under `assets/generated/`, locale strings and generated READMEs, `configs/profile.json` and `configs/data/` |

`tooling/tests/test_licensing.py` fails if a file has no license, if a
source file lacks its SPDX header, or if `LICENSE`, `REUSE.toml` and the
shipped license texts disagree. Add new files to the matching entry of
`REUSE.toml`, or give source files an SPDX header, in the same commit.

### Using the repository for your own profile

The engine is free to fork and adapt. The Creative Works are not, so before
publishing a derived profile (`LICENSE`, Section 4):

1. Replace `assets/profile/banner.webp` and the `*.webp` backgrounds, and
   record your own generation prompts next to them. The prompts in this
   repository are a reference you may reuse.
2. Rewrite the texts in `locales/readme/*/strings.json`.
3. Replace `configs/profile.json` (identity, contacts, projects) and
   remove `configs/data/snapshot.json`; `--fetch` writes your own.
4. Change the palette in `configs/theme.json` to give the profile its own
   look.
5. Update `github.repository == 'Mioji/Mioji'` in
   `.github/workflows/profile.yml` to your `<owner>/<repo>` slug so the
   scheduled refresh job runs on your fork.
6. Run `python tooling/generate.py --fetch` and commit the result.

## Data contract

All requests use the GitHub REST API, version `2022-11-28`.

| Displayed value | Source | Rule |
| --- | --- | --- |
| Public repositories | `/users/{user}/repos?type=owner` | Owned public repositories, forks and archived ones included. The count must equal `public_repos` of `/users/{user}`, otherwise the data changed mid-collection and the run fails. |
| Stars, forks, open issues and PRs | Repository listing | Sums over owned repositories. GitHub reports open issues and pull requests as one number. |
| Followers, following, gists | `/users/{user}` | Current values. |
| Public activity | `/users/{user}/events/public` | Up to three pages of 100 events, the most GitHub serves, counted per UTC calendar day over the 30 days ending on the snapshot date. |
| Project stars | Listing plus `/repos/{owner}/{name}` | Owned repositories plus public catalog repositories owned by others. Private catalog entries are never requested and show an em dash. |

Pagination follows `Link: rel="next"` headers. Collection is
all-or-nothing: the snapshot is replaced only after every response passed
validation, so a failed fetch leaves the committed state untouched.

## Automation and failure handling

- **Schedule.** The workflow runs daily at 06:23 UTC, on every push to
  `main`, on pull requests (verification only) and on manual dispatch.
- **Gating.** The refresh job runs only after linting, type checking, tests
  and `--check` have passed.
- **Freshness.** Panels show the snapshot time. If a refresh fails, the
  previous snapshot stays published and the next scheduled run retries.
- **Network.** Transient errors are retried with exponential backoff and
  jitter. Rate limits honour `Retry-After` and `X-RateLimit-Reset`; a
  requested wait above 30 seconds aborts the run instead of idling.
- **Writes.** Outputs are staged in a temporary directory and moved into
  place one by one. Any failure restores the files already replaced, so the
  working tree is either fully updated or unchanged.
- **Security.** Workflow permissions default to none and are granted per
  job. Actions are pinned to commit SHAs and development tools to hashes.
  The API client follows redirects only within `https://api.github.com`, so
  the token cannot leak to another host. Every generated SVG is checked
  against an element and attribute allow-list before it is written.
